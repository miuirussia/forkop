# Настройки

Параметры вкладки **Настройки** сгруппированы по категориям. Обновления списков настраиваются на вкладке **Геоданные**. В скобках стоит имя параметра в разделе `settings` файла `/etc/config/forkop`.

## DNS

| Параметр | По умолчанию | Что делает |
| --- | --- | --- |
| **DNS-сервер** (`dns_server`) | `77.88.8.8` | основные DNS-серверы. Протокол задаётся префиксом, несколько серверов страхуют друг друга. [Подробнее](/dns/) |
| **Режим опроса основного DNS** (`dns_main_fallback_strategy`) | Параллельно | спрашивать несколько серверов сразу или по очереди |
| **Bootstrap DNS-серверы** (`bootstrap_dns_server`) | `77.88.8.8` | узнают адреса DNS-серверов, заданных именем, и серверов прокси. IP-адреса или **DNS сети по умолчанию** (`network`) |
| **Режим опроса Bootstrap DNS** (`dns_bootstrap_fallback_strategy`) | Параллельно | то же для bootstrap-серверов |
| **Перезапись TTL для DNS** (`dns_rewrite_ttl`) | `60` | сколько секунд устройства хранят ответ |
| **Стратегия DNS** (`dns_strategy`) | Предпочитать IPv4 | какие адреса ядро запрашивает для своих соединений |
| **DNS через секцию** (`dns_detour_enabled`, `dns_detour_section`) | выключено | отправлять запросы основных DNS-серверов для доменов вне правил через выбранную секцию. DNS внутри секции следует её маршруту, у **Bypass** идёт напрямую |
| **Статичные DNS записи** (`static_hosts_text`) | пусто | постоянные адреса доменов в формате hosts |
| **Тайм-аут DNS** (`dns_timeout`) | `10s` | сколько ждать ответа DNS-сервера |
| **DNS вне правил** (`unmatched_dns_mode`) | Forkop | кто отвечает на домены вне секций. **Forkop** отвечает основными DNS-серверами, **Роутер** отдаёт их dnsmasq со всеми его настройками, например AdGuard Home |

**DNS сети по умолчанию** берёт адреса из `/tmp/resolv.conf.d/resolv.conf.auto` (на старых OpenWrt — `/tmp/resolv.conf.auto`). Можно оставить только этот пункт или добавить явные адреса для подстраховки. Если сетевых DNS нет и другие bootstrap-серверы не заданы, Forkop сообщит об ошибке. Адреса перечитываются при применении конфигурации; после их смены примените настройки заново или включите мониторинг WAN-интерфейса.

## Сеть

| Параметр | По умолчанию | Что делает |
| --- | --- | --- |
| **Исключить устройства из маршрутизации** (`routing_excluded_ips`) | пусто | устройства, которых Forkop не трогает: ни трафик, ни DNS. Пункт **Система** означает сам роутер |
| **Сетевой интерфейс источника** (`source_network_interfaces`) | `br-lan` | откуда Forkop забирает трафик устройств. Гостевую сеть добавляют сюда, если она должна идти через Forkop |
| **Включить выходной сетевой интерфейс** (`enable_output_network_interface`), **Выходной сетевой интерфейс** (`output_network_interface`) | выключено | через какой интерфейс ядро выходит в интернет. Без настройки соединения ядра идут по маршрутам роутера, как у любой другой программы, с отдельными маршрутами к серверам, mwan3 и политикой маршрутизации. Задавайте интерфейс, только если ядро должно выходить через него в обход маршрутов. В списке те же провайдеры и туннели, что у поля [Сетевой интерфейс](/connections/interface#что-есть-в-списке) секции |
| **Мониторинг интерфейса** (`enable_badwan_interface_monitoring`) | выключено | следить за WAN-интерфейсами и применять конфигурацию заново, когда интерфейс снова поднимается. Помогает, если после переподключения провайдера ядро теряет интернет |
| **Наблюдаемые интерфейсы** (`badwan_monitored_interfaces`) | пусто | за какими интерфейсами следить |
| **Задержка при мониторинге интерфейсов** (`badwan_reload_delay`) | `2000` | сколько миллисекунд ждать после поднятия интерфейса |
| **Запрашивать WARP через секцию** (`warp_profiles_via_proxy`, `warp_profiles_via_proxy_section`) | выключено | регистрировать и получать профили Cloudflare WARP через секцию. [Подробнее](/tunnels/warp#создать-туннель) |

## Трафик

| Параметр | По умолчанию | Что делает |
| --- | --- | --- |
| **Отключить QUIC** (`disable_quic`) | выключено | отклонять QUIC, то есть HTTP/3 по UDP, в перехваченном трафике. Браузеры перейдут на TCP, это помогает, когда видео через VPN тормозит |
| **Торренты напрямую** (`bittorrent_direct`) | выключено | соединения BitTorrent, распознанные в перехваченном трафике, отправлять напрямую мимо секций |

## YACD

| Параметр | По умолчанию | Что делает |
| --- | --- | --- |
| **Включить YACD** (`enable_yacd`) | выключено | панель [YACD](https://github.com/MetaCubeX/Yacd-meta) по адресу `http://<роутер>:9090/ui`: соединения, группы и логи в интерфейсе Clash. При первом включении ядро скачивает панель с GitHub. Ссылка под переключателем открывает панель уже с ключом Clash API |
| **Включить доступ YACD WAN** (`enable_yacd_wan_access`) | выключено | открыть панель и Clash API на всех интерфейсах, а не только дома. Порт нужно отдельно открыть в файерволе |
| **Ключ Clash API** (`yacd_secret_key`) | выключено | без него Clash API не отвечает, поэтому чужие устройства в сети не видят соединения и не переключают серверы. С этим ключом входят YACD и другие клиенты Clash API. Пустое поле Forkop заполнит новым ключом при следующем запуске или применении настроек |

## Измерение задержки

| Параметр | По умолчанию | Что делает |
| --- | --- | --- |
| **Точное измерение задержки** (`unified_delay`) | включено | засчитывать второй запрос через уже открытое соединение, без установки соединения и рукопожатий |
| **URL для тестирования задержки** (`latency_test_url`) | `https://www.gstatic.com/generate_204` | адрес для проверки задержки на дашборде |

## Служба

| Параметр | По умолчанию | Что делает |
| --- | --- | --- |
| **Включить VPN-сервер** (`enable_vpn_server`) | выключено | показать вкладку VPN-сервера и запускать настроенные на ней серверы. При выключении серверы и их клиенты сохраняются, но не запускаются; автоматически открытые порты закрываются после применения настроек |
| **Путь к файлу конфигурации** (`config_path`) | `/etc/sing-box/config.json` | куда Forkop пишет конфигурацию ядра. Во флеш-памяти она переживает перезагрузку, в `/tmp` не расходует флеш-память и собирается заново при запуске |
| **Путь к файлу кэша** (`cache_path`) | `/tmp/sing-box/cache.db` | кеш ядра: FakeIP, скачанные списки и подписки, ручной выбор серверов, профили WARP. В `/tmp` он пропадает при перезагрузке, во флеш-памяти сохраняется, но постоянно её перезаписывает |
| **Уровень логов** (`log_level`) | `warn` | подробность журнала ядра: `trace`, `debug`, `info`, `warn`, `error`, `fatal`, `panic`. На строки самого Forkop не влияет |

::: warning Кеш во флеш-памяти
Ядро пишет в кеш постоянно: каждый новый домен FakeIP и каждое обновление списков. На недорогих роутерах это изнашивает флеш-память, поэтому без особой причины держите кеш в `/tmp`.
:::

## Autodetect

Откройте **Настройки → Autodetect**, включите функцию, выберите секцию сравнения и примените настройки.

| Параметр | По умолчанию | Что делает |
| --- | --- | --- |
| **Включить Autodetect** (`enable_autodetect`) | выключено | показать вкладку Autodetect и проверять подозрительные HTTPS-соединения |
| **Секция сравнения Autodetect** (`autodetect_proxy_section`) | не выбрана | секция для сравнения с прямым доступом |
| **Порты HTTPS** (`autodetect_ports`) | `443` | TCP-порты для наблюдения, по одному в строке, например `443` и `8443`. Проверяются только HTTPS-соединения |
| **Тайм-аут запроса, секунды** (`autodetect_timeout`) | `8` | время одной проверки, от 1 до 60 секунд |
| **Подтверждений подряд** (`autodetect_confirmations`) | `2` | сколько сравнений должны подтвердить ограничение, от 1 до 5 |
| **Порог зависания, секунды** (`autodetect_stall_timeout`) | `9` | сколько ждать без прогресса входящих данных, от 3 до 300 секунд |
| **Объём пробного ответа, КиБ** (`autodetect_response_limit`) | `64` | ограничение загружаемого фрагмента, от 1 до 1024 КиБ |
| **Повторная проверка, минуты** (`autodetect_recheck_interval`) | `15` | срок результата и пауза перед повторной проверкой, от 1 до 1440 минут |
| **Размер истории результатов** (`autodetect_history_limit`) | `100` | число сохраняемых результатов, от 10 до 100 |

При выключении функции выбранная секция и параметры сохраняются.

При включённом Autodetect Forkop передаёт sing-box TCP-соединения на выбранных портах, в том числе к сайтам, которых нет в секциях. Это увеличивает нагрузку на процессор роутера. Исключённые устройства, локальные адреса и явные правила обхода сохраняют приоритет. Трафик самого sing-box повторно не перехватывается.

Ядро наблюдает активные и недавно закрытые HTTPS-соединения, которые идут напрямую. Отсутствие ответа, раннее закрытие или остановка счётчика входящих данных запускают проверку. Домены вводить не нужно: откройте проблемный сайт на устройстве, чей трафик проходит через Forkop. Проверки продолжаются после закрытия страницы.

Проверка делает HTTPS-запрос с исходным доменом, портом и проверкой сертификата напрямую и через выбранную секцию. Когда IP назначения известен, оба запроса идут к нему с одинаковым SNI. Загружается ограниченный фрагмент ответа — по умолчанию до 64 КиБ; перенаправления не выполняются. Это позволяет заметить и зависание передачи после успешного TLS-рукопожатия. Одновременно выполняются не более двух запросов; результаты и наблюдения хранятся в ограниченных таблицах в памяти, без записи во флеш.

Статус **Вероятная блокировка** появляется после заданного числа неудачных проверок напрямую при успешных проверках через выбранную секцию. Подтверждения должны идти подряд. **Ограничение HTTP** — коды 403/451 напрямую при успешной проверке через секцию. Если не работают оба пути, результат **Не определено**. Рабочий прямой запрос означает только доступность проверенного HTTPS-адреса: антибот, отдельные URL, QUIC/HTTP3, ограничения по отпечатку браузера и подмена DNS требуют отдельной диагностики. По одному тайм-ауту причина не устанавливается.

Во вкладке показаны домен, адрес назначения, устройство, повод проверки и ответы обоих маршрутов. По умолчанию хранятся последние 100 результатов за 15 минут; перезапуск ядра очищает историю. Проверки не изменяют правила маршрутизации или статистику задержек URLTest.

## Обновления списков

Интервал автообновления и секция для загрузки списков настраиваются на вкладке [Геоданные](/geodata).

| Параметр | По умолчанию | Что делает |
| --- | --- | --- |
| **Автообновление** (`list_update_enabled`) | включено | обновлять встроенные списки и удалённые наборы правил по расписанию |
| **Интервал обновления** (`update_interval`) | `1d` | как часто обновлять списки, например `12h`, `1d` или `3d` |
| **Секция для загрузки** (`download_lists_via_proxy_section`) | Напрямую | скачивать встроенные списки и удалённые наборы правил напрямую или через выбранную секцию; флаг `download_lists_via_proxy` сохраняется автоматически |
