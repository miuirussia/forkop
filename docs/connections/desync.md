# Desync

Действие **Desync** отправляет трафик напрямую через встроенный движок sing-box-forkop, меняя начальный TCP/TLS/HTTP-обмен или добавляя UDP fake-пакеты. Прокси-сервер для этой секции не нужен. Desync не скрывает IP-адрес назначения и сам по себе не шифрует HTTP.

Нужен sing-box-forkop **1.14.4-r20 или новее**. Forkop читает версию из установленного бинарного файла и требует корректный ответ `sing-box desync capabilities`: маркер `forkop-desync-v1`, версию контракта 1, подтверждение поддержки и таблицы возможностей. Отсутствие команды или неполный ответ отклоняются. Перед применением параметры проверяет тот же core. Ошибки неподдерживаемых сочетаний, платформы или прав показываются с причиной.

## Маршрутизация и DNS

Условия секции и порядок секций работают как у Connection: домены, подсети IPv4/IPv6, устройства, порты, списки и rule sets. Доменам выдаётся FakeIP, а после сопоставления выбирается нужный реальный адрес. Секция получает свой DNS-резолвер; сам outbound использует Bootstrap DNS, чтобы разрешение имени не замкнулось на себя.

TCP и UDP перехватываются существующими правилами nftables. Обычные и raw-сокеты core должны сохранять обходную марку Forkop `0x08000000`; исходящий интерфейс задаётся общей настройкой **Исходящий сетевой интерфейс**. Глобальное **Отключить QUIC** проверяется раньше секционных правил: Desync не отменяет этот запрет.

## Пресеты и формат

| Пресет | Начальное поведение |
| --- | --- |
| `auto` | Adaptive: ограниченный выбор стратегии и обучение |
| `custom` | Явные ручные параметры; для фиксации задайте `auto_tune: false` |
| `split`, `disorder`, `tlsrec`, `fake`, `fake_split`, `oob` | Соответствующий TCP-режим |
| `GT1`–`GT4` | UDP `auto`, 1–4 повтора, диапазон исходящих пакетов `1:1`–`1:4`, TCP `none` |

Доступные TCP-режимы: `none`, `split`, `disorder`, `tlsrec`, `fake`, `fake_split`, `oob`, `multi_split`, `fake_disorder`, `multi_disorder`, `disoob`, `hostfakesplit`. Ручные поля переопределяют пресет. Отсутствие поля отличается от явно заданных `false` и `0`; они сохраняются при импорте и генерации. Значение `auto_tune: false` отключает Adaptive даже с пресетом `auto`.

Канонический UCI-формат — действие `desync` и JSON-объект `desync_options`:

```uci
config section 'desync_web'
    option enabled '1'
    option action 'desync'
    option destinations 'example.org'
    option desync_options '{"preset":"custom","mode":"multi_split","split_pos":"sni,midsld+1","auto_tune":false}'
```

Стратегия хранится только в `desync_options`. В форме можно импортировать JSON или строку `key=value`, например:

```text
preset=custom mode=fake_split split_pos=midsld ttl=3 fooling=badseq auto_tune=false
```

Токены разделяются пробелами; строковые значения допускают JSON-кавычки. `fake_sni_pool` принимает список через запятую или JSON-массив; `adaptive` — JSON-объект. Повторяющиеся и неизвестные ключи отвергаются. При экспорте JSON сохраняет всю стратегию, включая Advanced и Adaptive. Маркеры разреза: положительное смещение в байтах, `sni`, `sniext`, `host`, `midsld`, `endhost`, `extlen`; символьный маркер может иметь `+N` или `-N`. Список содержит до 16 позиций.

| Поля | Назначение и ограничения |
| --- | --- |
| `split_pos`, `tlsrec_first`, `delay` | Позиции, предварительное преобразование TLS records и задержка до 1 секунды |
| `tlsrec_pos` | Независимые границы TLS records при `mode: tlsrec` или `tlsrec_first: true`; без них используется `split_pos`. Числовая граница должна быть больше 5 |
| `segment_order` | Порядок TCP-сегментов: `forward`, `reverse`, `sni_last` либо перестановка с 1, например `2,1,3`. Требует сегментации и Linux raw TCP |
| `fake_placement`, `fake_delay` | Fake перед сегментами (`before`), между ними (`between`) или в обоих местах (`before_between`). Пауза после каждого fake — до 1 секунды; без неё наследуется `delay`, явный `0s` отключает паузу fake |
| `fake_tls_random`, `fake_tls_size`, `fake_tls_template` | Обновление Random/SessionID/key shares fake, точный размер ClientHello с заголовками (0 отключает, максимум 60000), шаблон `original` или `compact` |
| `http_mod` | Уникальные токены `hcsmix,dcsmix,rmspace`: регистр Host, регистр домена и перенос начальных пробелов в конец значения. Работает и при TCP `none` |
| `hostfake_mode` | Для `hostfakesplit`: `legacy` или подмена имени той же длины `replace`. Подмена несовместима с custom payload и преобразованиями fake TLS |
| `fake_sni`, `fake_host`, `fake_payload`, `fake_sni_pool` | Имя или payload fake; payload — base64, пул до 64 имён |
| `repeats`, `ttl`, `fooling`, `seqovl`, `autottl` | Повторы 1–16, TTL 1–255, метод fake, overlap и оценка TTL |
| `ipfrag`, `syndata`, `wsize`, `wscale` | Начальные IP/TCP-механизмы Linux; реальные ограничения проверяет core, `syndata` — base64 |
| `udp_mode` | `none`, `quic`, `stun`, `auto` |
| `udp_fake_payload`, `udp_ttl`, `udp_repeats` | UDP fake, TTL 1–255, 1–16 повторов |
| `udp_out_range` | Диапазон исходящих пакетов одного потока и назначения, начиная с 1, включительно, не выше 1024 |
| `udp_keep_socket`, `udplen` | Жизненный цикл UDP-сокета и протокольно допустимое изменение длины; неподдерживаемое значение даёт ошибку |
| `quic_desync`, `quic_repeats` | Отдельное включение QUIC и 0–16 повторов; 0 наследует `udp_repeats`. Требуется UDP `quic` или `auto`; положительное число повторов несовместимо с `quic_desync: false` |
| `quic_split_pos`, `quic_order` | Разрезы и порядок CRYPTO frames внутри одного QUIC Initial: смещения в CRYPTO stream или семантические маркеры; порядок как в `segment_order`. Требуются UDP `quic`/`auto`, включённый QUIC desync и разрезы для явного порядка |
| `auto_tune`, `adaptive` | Adaptive и его лимиты: `max_attempts`, `max_concurrent`, `max_entries`, `ttl`, `timeout`, `max_buffer`, `network_id` |

Нельзя задавать `detour`, `routing_mark` и другие dialer-поля внутри стратегии: ими управляет Forkop. JSON секции ограничен 32 КиБ. Параметры fake применимы к fake-режимам, UDP-параметры требуют включённого `udp_mode`. При несовместимости core выдаёт ошибку, а не игнорирует настройку.

Новые поля доступны в **Расширенных настройках**, в группах TCP и UDP. Их поддержку Forkop проверяет по обязательному ответу `desync capabilities` установленного ядра. Пустое поле формы наследует профиль; явные `false`, `0`, `0s` и пустые строки в импортированном JSON сохраняются при загрузке, экспорте и генерации конфигурации.

Например, независимые разрезы TLS records и TCP с заданным порядком сегментов:

```text
preset=custom auto_tune=false mode=multi_split tlsrec_first=true tlsrec_pos=midsld split_pos=sniext+1,endhost-1 segment_order=2,1,3
```

Количество сегментов для перестановки проверяется ядром по конкретному первому сообщению. QUIC-преобразования сохраняют номер пакета и handshake-байты и не переставляют разные дейтаграммы.

Единый список `fooling` для core, UCI и формы: пустая строка, `none`, `badseq`, `badack`, `badsum`, `md5`, `md5_badack`, `badseq_badack_badsum`, `datanoack`, `hopbyhop`, `destopt`, `ipfrag`, `ts`, `badtimestamp`. Произвольные другие комбинации отклоняются. `badtimestamp` — синоним `ts` с сохранением исходного написания при импорте/экспорте; оба требуют согласованных TCP timestamps. `ipfrag` фрагментирует fake с размером 48 байт, если размер не задан отдельным параметром `ipfrag`. Пустая строка и `none` сохраняют обязательную защиту sequence range, отключая дополнительные методы fooling.

`udp_keep_socket: true` сохраняет обычный UDP-сокет сессии для обмена и fake-серий. При `false` fake-серия использует временный raw-инжектор, который закрывается после серии; сокет ответов и исходный порт сессии сохраняются. Для этого варианта нужен Linux с `CAP_NET_RAW`. Марка и интерфейс должны сохраняться и на raw-сокете.

TTL fake выбирается по фактическому назначению каждого пакета, включая IPv4 после IPv6 на одном dual-stack сокете. После серии исходные TTL/hop limit восстанавливаются.

`udplen` обрабатывает STUN через PADDING с сохранением MESSAGE-INTEGRITY и обновлением FINGERPRINT. Для QUIC изменение длины допустимо у распознанного Initial v1/v2/draft-29: core пересобирает защищённый пакет с PADDING, AEAD и header protection. Остальные защищённые пакеты не дополняются произвольными байтами. `quic_desync: false` в UDP `auto` отключает QUIC-преобразования, сохраняя обработку STUN.

Перестановка TCP, raw fake, overlap и фрагментация требуют подходящего Linux и прав `CAP_NET_RAW`/`CAP_NET_ADMIN`. `syndata` — fake-полезная нагрузка SYN с заведомо неверной контрольной суммой, до настоящего SYN ядра; она не становится прикладными данными сервера. `wscale`, включая явный 0, задаётся до SYN и проверяется после установления соединения. Временный размер receive buffer восстанавливается после рукопожатия; Linux при этом может оставить буфер с фиксированным пределом вместо автоматической настройки. Если конкретный эффект нельзя обеспечить, core возвращает ошибку.

## Ссылки и каскады

Desync открывает собственный прямой сокет. Внутри секции Desync нельзя оставлять ссылки, подписки, интерфейсы, туннели, JSON outbound, группы или каскад в другую секцию.

Connection может выбрать самостоятельную секцию Desync выходом **каскада ссылки или подписки**. В этом случае десинхронизируется соединение с сервером прокси; это не гарантирует изменения трафика внутри зашифрованного туннеля. Каскад обёртки **Туннель** в Desync отклоняется. JSON outbound сохраняет собственные правила core и не добавляет обёртку Desync поверх чужого сокета.

На секцию Desync можно ссылаться из маршрутизации серверов, DNS и загрузки внешних ресурсов. Она должна быть включена. Правила секции определяют перехват обычного трафика; явная ссылка использует её outbound непосредственно.

## Подбор и диагностика

Подбор доступен и в окне добавления секции, до её сохранения. Он проверяет стратегии из формы; идентификатор секции служит только меткой задания и не требует существующего outbound. Найденный вариант можно перенести в форму и сохранить вместе с новой секцией.

Подбор запускает отдельный процесс с пробами через **тот же установленный core**, собственной конфигурацией и обходной маркой Forkop. Активные секции и их файл конфигурации не изменяются. Пробы используют прямой Bootstrap DNS и общий исходящий интерфейс. TLS и QUIC проверяют настоящее рукопожатие и сертификат; HTTP выполняет ограниченный GET без перехода по редиректам. Для скорости выбирайте URL с достаточно большим телом ответа. Для TLS/QUIC цель задаётся как `host:port` или `[IPv6]:port`, для HTTP — HTTP(S) URL без учётных данных и фрагмента.

Одновременно работает одно задание: до 8 ручных кандидатов по 4 КиБ каждый, 1–3 повтора, по одной пробе, тайм-аут пробы 1–15 секунд, общий бюджет 1–120 секунд, до 1 МиБ тела ответа на пробу. Стратегии Adaptive не измеряются как ручной кандидат. Стабильность оценивается по успешным повторам; задержка и скорость показываются только при наличии соответствующего измерения. Результаты для одного провайдера не доказывают эффективность у другого.

Отмена останавливает текущую пробу и последующие. Дедлайн принудительно завершает зависший дочерний процесс. Временные options/output/error-файлы удаляются после завершения; результаты остаются в `/var/run/forkop/desync` до 15 минут и ограничены 16 заданиями. Остановка службы также запрашивает отмену подборов.

**Применить как custom** в интерфейсе переносит результат в форму. Обычные **Сохранить** и **Применить** сохраняют его и перезагружают службу. Подбор сам этого не делает.

Диагностика открывается кнопкой **Info** на карточке Desync в **Дашборде** и сразу загружает данные выбранной секции: текущую стратегию, причину смены, число записей обучения и активных попыток у работающего core. В этом же окне можно обновить данные и очистить результаты обучения. Исходный JSON раскрывается отдельно по нажатию **Показать**. Очистка идёт через авторизованный API core, без параллельного открытия `cache.db`. Обучение разделяется по outbound, параметрам и сетевому контексту. При отключённом cache file core обучается в памяти; при изменении конфигурации используется другой раздел статистики.

Для ещё не сохранённой секции диагностика возвращает пустой список outbound, чтобы форма показала подсказку о сохранении и применении. Очистка обучения для такой секции отклоняется и не затрагивает другие секции.

## Backend API

Диагностика показывает общее число изученных назначений и ограниченную выборку
последних записей. Ответ core ограничен по размеру для транспорта rpcd; полная
история остаётся в кеше и продолжает участвовать в выборе стратегий.

Используется авторизованный ubus-объект `forkop`. Каждый метод принимает `payload`, JSON-строку объекта запроса; `ubus_rpc_session` передаёт существующий транспорт LuCI. Ответ: `{ "success": true, ... }` или `{ "success": false, "message": "причина" }`.

| Метод | Запрос | Доступ |
| --- | --- | --- |
| `desync_capabilities` | `{}` | read |
| `desync_diagnostics` | `{ "section": "desync_web" }`, секция необязательна | read |
| `desync_tune_start` | `section`, `target`, `protocol`; необязательные `candidates`, `timeout`, `repetitions`, `max_duration`, `max_bytes`, `concurrency: 1` | write |
| `desync_tune_progress` | `{ "id": "..." }` | read |
| `desync_tune_cancel` | `{ "id": "..." }` | write |
| `desync_apply_custom` | `{ "section": "desync_web", "options": {...} }` | write + UCI-сессия |
| `desync_clear_cache` | `{ "section": "desync_web" }`, секция необязательна | write |

`desync_apply_custom` предназначен для API-клиентов: переводит стратегию в `custom`, задаёт `auto_tune: false`, убирает Adaptive и сохраняет `desync_options` в UCI-сессии вызывающего. Он не вызывает commit, apply или restart. Интерфейс может заполнить форму локально и использовать обычный путь сохранения.

Секция для `desync_apply_custom` проверяется в UCI-сессии вызывающего: можно использовать новую секцию с типом `section` и действием `desync`, которая ещё не сохранена в общей конфигурации.

Задание возвращает `id`, `state` (`running`, `completed`, `cancelled`, `failed`), `total`, `completed`, `results`, `started_at` и после окончания `finished_at`. Результат пробы содержит нормализованные core `options`, `candidate`, `repetition`, `success`, `error`, а также доступные `protocol`, `latency_ms`, `duration_ms`, `bytes`, `throughput_bps`, `status`, `tls_version`. Развёрнутые параметры пресета сохраняют измеренное поведение при переводе в `custom`. Состояние `completed` означает окончание задания; успешность сети определяется отдельными результатами.

CLI использует те же имена методов и один JSON-аргумент, например `forkop desync_capabilities '{}'`. Стадирование через CLI требует `FORKOP_RPC_SESSION`; команды подбора не требуют передачи сессионного идентификатора в командной строке.

## Проверки

Тесты backend находятся в `tests/config/desync.test.uc`, `tests/singbox/desync*.test.uc`, `tests/service/desync.test.uc`. Они проверяют UCI, стратегии, каскады, генератор, DNS/FakeIP, приоритет QUIC, nft, обходную марку, версию/capabilities, изоляцию, прогресс, отмену, тайм-аут и стадирование UCI. Запуск: `tests/run.sh desync` с ucode `v0.0.20250529`; полный набор — `tests/run.sh`.

`python3 tests/service/desync-runtime.py --core /path/to/sing-box` на Linux проверяет настоящий worker, процессы и таймеры uloop, HTTP-пробы, повторения, ограничение тела, отмену с завершением дочернего core, тайм-аут, неизменность отдельного работающего core и авторизацию диагностики/очистки. Нужен ucode, собранный с `ULOOP_SUPPORT=ON`; подменяется только UCI. Скрипт создаёт собственные временные файлы, HTTP-сервер и экземпляр core и завершает их после проверки.

`python3 tests/service/desync-conformance.py --core /path/to/sing-box` проверяет значения `fooling` и новые настройки из общих с тестами формы и UCI файлов `tests/fixtures/desync_fooling.json` и `tests/fixtures/desync_extensions.json` через настоящий core CLI, UCI import/export и канонический JSON. Проверяются также неизвестные и несовместимые комбинации, нормализация длительностей и сохранение явных `false`/`0`.

Эти проверки не заменяют пакетные испытания ядра. Порядок TCP-сегментов, отсутствие fake в прикладном потоке, точные SYN/window-параметры, IPv6/NAT/MTU, QUIC/STUN, восстановление сокетов и гонки проверяются Linux-стендом и тестами sing-box-forkop. Прошедшая валидация не обещает, что Linux разрешит raw socket или TCP_REPAIR во время соединения: конкретная ошибка прав или ядра возвращается при сетевой операции.
